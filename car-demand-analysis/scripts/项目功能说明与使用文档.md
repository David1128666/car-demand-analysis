## 1. 项目概述

### 1.1 项目背景

随着汽车市场快速发展，消费者对汽车的需求日益多样化、个性化。传统市场调研方式存在数据滞后、样本有限等问题，难以满足实时洞察市场需求的要求。本系统构建了一套基于大数据的汽车需求分析平台，通过实时采集和分析海量汽车行为数据，挖掘消费者需求趋势，为汽车厂商和经销商提供数据决策支持，同时为消费者提供个性化购车推荐服务。

### 1.2 核心目标

| 目标 | 说明 |
|------|------|
| **实时数据分析** | Kafka 实时接收用户行为数据，Spark Streaming 实时处理，第一时间捕捉市场动态 |
| **离线趋势挖掘** | Spark SQL 批量分析历史数据，发现长期趋势和隐藏规律 |
| **个性化推荐** | 基于协同过滤和内容推荐算法，为用户提供精准购车建议 |
| **可视化展示** | 前后端分离架构，ECharts 数据看板，直观展示分析结果 |

## 2. 技术架构

### 2.1 整体架构（Lambda 架构）

系统采用 Lambda 架构，同时支持实时流处理（Speed Layer）和离线批量处理（Batch Layer），最后在服务层统一融合。

```
┌──────────────────────────────────────────────────────────────┐
│                        数据源层                                │
│  simulator/generate_data.py → 生成5类JSON模拟数据              │
│  simulator/send_data.sh      → 逐行发送到Flume监控目录          │
│  simulator/start-flume.sh    → TAILDIR Source监控文件入Kafka   │
└────────────────────────┬─────────────────────────────────────┘
                         ▼
┌──────────────────────────────────────────────────────────────┐
│                    Kafka 消息队列                              │
│  car-user-behavior | car-search | car-consult                │
│  car-price-quote   | car-loan-inquiry                        │
└────────────────────────┬─────────────────────────────────────┘
                         ▼
┌──────────────────────────────────────────────────────────────┐
│                  Spark Structured Streaming                   │
│                (realtime-analysis 模块)                        │
│  数据解析 → 清洗验证 → 窗口聚合 → foreachBatch 写入 MySQL       │
└────────────────────────┬─────────────────────────────────────┘
                         ▼
┌──────────────────────────────────────────────────────────────┐
│                      MySQL 8.0 数据库                          │
│  user_behavior | realtime_stats | daily_stats                │
│  user_profile  | recommendation | car_info                   │
└──────┬──────────────────┬──────────────────┬─────────────────┘
       │                  │                  │
       ▼                  ▼                  ▼
┌────────────┐  ┌──────────────┐  ┌──────────────────┐
│ 离线分析    │  │  推荐引擎     │  │  后端 API 服务    │
│ Spark SQL  │  │  Spark MLlib │  │  Python FastAPI  │
│ 趋势/画像   │  │  ALS/CF/CB  │  │  RESTful 接口     │
└─────┬──────┘  └──────┬───────┘  └────────┬─────────┘
      │                │                   │
      └────────────────┼───────────────────┘
                       ▼
┌──────────────────────────────────────────────────────────────┐
│                  前端 Vue.js 3 + ECharts                       │
│  数据看板 | 分析页 | 市场页 | 车型页 | 推荐页 | 管理后台         │

```

## 3. 模块功能详述

### 3.1 公共模块（`common/`）

**路径：** `car-demand-analysis/common/`
**语言：** Scala
**功能：** 为三个数据处理模块提供共享的数据模型和工具类。

| 文件 | 说明 |
|------|------|
| `config/AppConfig.scala` | 读取 `application.conf` 配置（Kafka地址、MySQL连接、Spark参数） |
| `model/UserBehavior.scala` | 用户行为数据模型（behavior_id, user_id, car_id, behavior_type等） |
| `model/CarSearch.scala` | 搜索数据模型（search_id, user_id, search_keyword等） |
| `model/CarConsult.scala` | 咨询数据模型（consult_id, car_id, consult_type, followup_status） |
| `model/CarPriceQuote.scala` | 报价数据模型（quote_id, original_price, quoted_price, discount_rate） |
| `model/CarLoanInquiry.scala` | 贷款询价模型（loan_id, loan_type, loan_amount, interest_rate, credit_score） |
| `util/JsonParser.scala` | JSON 解析工具（Jackson 封装） |
| `util/MySQLUtils.scala` | MySQL JDBC 连接池工具 |

### 3.2 实时分析模块（`realtime-analysis/`）

**路径：** `car-demand-analysis/realtime-analysis/`
**语言：** Scala + Spark Structured Streaming
**启动方式：** `./scripts/run-realtime.sh` 或 IDEA 运行 `RealTimeAnalysisApp`
**运行模式：** 常驻进程，持续运行

**功能描述：**
从 Kafka 消费 5 个 Topic 的实时数据，使用 Spark Structured Streaming 进行流式处理，通过 `foreachBatch` 将计算结果批量写入 MySQL。

**处理器明细：**

| 处理器 | Kafka Topic | 写入 MySQL 表 | 处理逻辑 |
|--------|-------------|---------------|----------|
| `UserBehaviorProcessor` | car-user-behavior | realtime_stats | 按品牌/车型/小时统计 PV、UV、浏览/搜索/咨询/收藏次数 |
| `SearchStatsProcessor` | car-search | search_log | 解析搜索关键词，统计热门搜索词频次 |
| `ConsultStatsProcessor` | car-consult | operation_log | 统计咨询量、跟进状态分布、留资率 |
| `PriceQuoteProcessor` | car-price-quote | realtime_price_stats | 统计报价均价、折扣率、降价幅度分布 |
| `LoanInquiryProcessor` | car-loan-inquiry | realtime_loan_stats | 统计贷款申请量、通过率、平均贷款金额、信用分分布 |

**关键配置：**

| 参数 | 推荐值 | 说明 |
|------|--------|------|
| `trigger interval` | 5秒 | 微批次触发间隔 |
| `watermark` | 10分钟 | 迟到数据容忍度 |
| `checkpoint` | `checkpoint/` 目录 | 状态容错恢复 |
| `foreachBatch 并行度` | 1 | 保证 MySQL 写入有序 |

### 3.3 离线分析模块（`offline-analysis/`）

**路径：** `car-demand-analysis/offline-analysis/`
**语言：** Scala + Spark SQL
**启动方式：** `./scripts/run-offline.sh [task]` 或 IDEA 运行 `OfflineAnalysisApp`
**运行模式：** 单次批处理任务，建议 crontab 定时调度

**分析任务：**

| 任务参数 | 对应类 | 功能 |
|----------|--------|------|
| `trend` | `TrendAnalysis` | 品牌趋势：按天统计各品牌 PV/UV/搜索量/咨询量变化趋势 |
| `profile` | `UserProfileAnalysis` | 用户画像：按用户聚合行为，计算偏好品牌/车型/价格/燃料类型标签 |
| `preference` | `CarPreferenceAnalysis` | 车型偏好：统计车型热度排行、地区分布、燃料类型偏好 |
| `daily` | `DailyStatsAnalysis` | 日报表：汇总当日所有指标，生成 daily_stats 表数据 |
| `all` | 全部串行执行 | 依次执行以上四个任务 |

**输出表：**

| 表名 | 说明 |
|------|------|
| `daily_stats` | 每日统计报表（品牌/车型/地区维度） |
| `user_profile` | 用户画像（偏好品牌/车型/价格/燃料+价值评分） |
| `car_preference_stats` | 车型偏好统计 |

### 3.4 推荐引擎模块（`recommendation-engine/`）

**路径：** `car-demand-analysis/recommendation-engine/`
**语言：** Scala + Spark MLlib
**启动方式：** `./scripts/run-recommendation.sh` 或 IDEA 运行 `RecommendationApp`
**运行模式：** 单次批处理任务，建议每天凌晨执行一次

**推荐流程（多路召回 + 加权排序）：**

```
用户行为数据 (MySQL)
    │
    ├──→ [召回层] ──────────────────────────┐
    │    ├─ 协同过滤召回 (ALS矩阵分解)        │
    │    ├─ 内容推荐召回 (品牌/车型/价格匹配)   │
    │    └─ 热门推荐召回 (PV排序, 冷启动降级)  │
    │                                        ▼
    │                              [排序层] RankingStrategy
    │                              加权融合: CF×0.5 + CB×0.3 + Hot×0.2
    │                                        │
    │                                        ▼
    │                              写入 MySQL recommendation 表
    │                              (user_id, car_id, score, reason, rec_type)
```

**核心类说明：**

| 类 | 算法 | 说明 |
|----|------|------|
| `CollaborativeFiltering` | ALS 矩阵分解 | 基于用户-车辆评分矩阵，分解出 user features + car features，预测缺失评分 |
| `ContentBased` | 余弦相似度 | 基于品牌/车型/价格/燃料类型多维度特征向量计算相似度 |
| `HotRecommendation` | 全局热度排序 | 基于 PV 统计排序，作为冷启动用户和新车型的降级策略 |
| `RankingStrategy` | 加权融合 | CF权重0.5 + CB权重0.3 + Hot权重0.2，去重去已购后写入结果 |

## 7. 数据流详解

### 7.1 实时数据流

```
simulator/generate_data.py        ← 生成 5 类 JSON 模拟数据（各 10000 条）
    ↓
simulator/send_data.sh loop       ← 逐行读取 + 更新时间戳 + 追加到 output/*.txt
    ↓
Flume TAILDIR Source              ← 监控 output/*.txt 文件变化
    ↓
Flume Memory Channel              ← 内存缓冲
    ↓
Flume Kafka Sink                  ← 投递到 Kafka 5 个 Topic
    ↓
Spark Structured Streaming        ← 消费 Kafka (realtime-analysis 模块)
    ↓ foreachBatch
MySQL (user_behavior + realtime_stats + search_log 等)
```

### 7.2 离线数据流

```
MySQL (user_behavior / 历史数据)
    ↓ JDBC读取
Spark SQL (offline-analysis 模块)
    ↓ 聚合/分组/窗口函数
MySQL (daily_stats / user_profile / car_preference_stats)
```

### 7.3 推荐数据流

```
MySQL (user_behavior + car_info)
    ↓ JDBC读取
Spark MLlib (recommendation-engine 模块)
    ├─ ALS 协同过滤  → 用户-车辆评分矩阵分解
    ├─ 内容相似度    → 车辆特征向量余弦相似度
    └─ 热度统计      → PV 降序排列
    ↓ 加权融合 (CF×0.5 + CB×0.3 + Hot×0.2)
MySQL (recommendation 表)
    ↓ 后端 API 查询
前端推荐页展示
```

### 7.4 前端请求流

```
浏览器 Vue.js
    ↓ HTTP (Axios + JWT Token)
Python FastAPI (backend)
    ↓ PyMySQL
MySQL (读取视图 v_car_full_info + 统计表 + 推荐表)
    ↓ JSON 响应
ECharts 渲染图表 / Element Plus 渲染表格
```

## 9. 推荐引擎详解

### 9.1 多路召回策略

**召回方式一：协同过滤（CollaborativeFiltering）**

- **算法：** ALS（Alternating Least Squares，交替最小二乘法）
- **原理：** 基于用户-车辆交互矩阵（行为次数作为隐式评分），分解为 user features 和 car features 两个低维矩阵，通过矩阵乘积预测用户对未交互车辆的评分
- **参数：** rank=10, iterations=10, lambda=0.01
- **适用场景：** 有足够行为数据的活跃用户

**召回方式二：基于内容推荐（ContentBased）**

- **算法：** 多维度特征向量余弦相似度
- **特征维度：** brand_id, car_type（one-hot）, fuel_type（one-hot）, price（归一化）
- **原理：** 根据用户历史行为过的车辆，计算特征向量均值作为用户偏好向量，再计算与候选车辆特征向量的余弦相似度
- **适用场景：** 行为数据较少的用户，车辆冷启动

**召回方式三：热门推荐（HotRecommendation）**

- **算法：** 全局 PV 降序排列
- **原理：** 统计所有车辆的总浏览量，按降序取 Top-N
- **适用场景：** 新用户冷启动、推荐结果不足时的兜底补全

### 9.2 加权融合排序

```
最终得分 = CF_score × 0.5 + CB_score × 0.3 + Hot_score × 0.2
```

- 对三路召回结果去重
- 过滤用户已经有过行为的车辆（避免推荐已浏览过的）
- 按加权得分降序排列
- 取 Top-20 写入 `recommendation` 表
- 为每一条推荐生成推荐理由（如"基于你的浏览偏好"、"热门车型"等）

## 10. 常见问题与排错

### 10.1 Maven 编译失败

```bash
# 问题：依赖下载失败
# 解决：检查网络，配置 Maven 国内镜像（阿里云）
# 或在 IDEA 中 Maven 面板 → Reload All Maven Projects

# 问题：scala-maven-plugin 报错
# 解决：确保 pom.xml 中 scala.version 与本地安装一致（2.13.14）
```

### 10.2 Kafka 连接失败

```bash
# 问题：Spark Streaming 报 "Failed to construct kafka consumer"
# 解决：检查 Kafka broker 是否启动，确认 application.conf 中地址正确
# 默认配置：kafka.bootstrap.servers = "node1:9092"
```

### 10.3 MySQL 写入失败

```bash
# 问题：foreachBatch 写入 MySQL 报错
# 解决：检查 MySQL 连接字符串、用户名密码、数据库名是否与 application.conf 一致
# 检查表是否已创建
```

### 10.4 前端 API 请求 401

```bash
# 问题：前端所有 API 请求返回 401 Unauthorized
# 解决：先访问 /login 登录获取 Token，或检查 localStorage 是否有有效 token
# Token 过期后会自动跳转登录页
```

### 10.5 推荐结果为空

```bash
# 问题：推荐页没有显示推荐结果
# 原因：推荐引擎尚未运行，或 user_behavior 表中无数据
# 解决：先运行 simulator 灌入数据 → 运行 realtime-analysis → 运行 offline-analysis → 运行 recommendation-engine
```

### 10.6 Spark 任务 OOM

```bash
# 问题：Spark 任务报 OutOfMemoryError
# 解决：增大 spark.executor.memory（如 --conf spark.executor.memory=2g）
# 或减小处理数据量
```
